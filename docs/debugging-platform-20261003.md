## Changes

- Admin API token acquisition and HTTP waits have independent 30-second bounds. HTML/empty/malformed JSON, malformed error envelopes and invalid page/details payloads become typed retryable UI errors rather than unchecked casts or stuck progress indicators. Network/TLS failures after a mutation starts report an unknown outcome; they never claim that nothing was submitted.
- Explicit identical mutation retries reuse an actor/path/canonical-payload idempotency key. There is no automatic mutation retry. `REQUEST_IN_PROGRESS` and `OPERATION_REVIEW_REQUIRED` preserve the key; review-required responses retain the server's operator guidance. Successful responses release the pending key. The backend workstream owns canonical server fingerprints, atomic reservation and durable unknown-state handling.
- Admin requests capture an account epoch, reject late token/network results after account changes, and stop pending writes before submission if the session changed. Access refreshes clear old roles immediately and reject stale same-account or prior-account results. Sign-out invalidates pending access and clears permissions before waiting for provider cleanup. One shared API client is now owned and disposed by the app provider.
- Resource pages reset on path changes, reject superseded loads, disable pagination/export while loading and dispose their search controller. Dashboard/analytics clear stale values and reject malformed or superseded results. Admin shell identity is tied to the signed-in UID.
- `quality.yml` is the reusable full CI gate. It includes Flutter/Admin quality, web asset checks, backend/security/dependency checks, rules, launch, messaging, attendance and isolated Functions integration, native compilation, secret scanning, native configuration tests and Windows Admin integration. `quality-complete` fails when any required job fails, is cancelled or is skipped.
- `firebase-release.yml` runs that quality gate once before its Firebase release chain. Existing merge, index-only and Functions-only entrypoints call it; deployment scope cannot skip quality. Production index/Functions/Hosting jobs require the production environment. Native internal distribution, Admin installer and PR preview workflows also depend on full quality. No workflow was dispatched.
- The web quality build, Firebase Hosting release and PR preview omitted environment placeholder configuration after building. All three now run `configure_web_environment.dart` before packaging, matching the local release script. Without it, the worker bridge and Firebase messaging worker contained unresolved placeholders. Workflow regressions reject omitted, late or mismatched-environment configuration.
- Admin's PowerShell build wrapper now explicitly checks Flutter and Inno Setup exit codes. A failed build cannot continue to package a stale existing executable merely because PowerShell's `ErrorActionPreference` did not catch a native exit code. Its guard regression extracts and tests only the wrapper with a fake command, without building or packaging.
- Application dependency installation in all CI workflows and the Admin packaging wrapper now uses `flutter pub get --enforce-lockfile`. The parent preserved the main application lockfile as a tracked candidate; the Admin lockfile was already tracked. A mutation regression removes the flag from each workflow command in turn and verifies that the gate rejects it. No dependency version was changed by this workstream.

## Recovery and acceptance boundaries

- Pending client mutation keys live in memory, scoped to the actor and exact payload, and survive sign-out/sign-in only while that process remains alive. Following an application restart, uncertain administrative operations require audit/operator reconciliation before resubmission; durable client recovery is not implemented. The HTTP timeout cannot cancel an already accepted backend mutation.
- The Windows test exercises the actual desktop renderer with isolated fixtures. It does not qualify live Firebase desktop auth, OAuth, administrator claims/roles, authenticated deployed API compatibility, real email/payment operations, a signed installer or installed-machine acceptance.
- Workflow YAML parsing and dependency regressions passed locally. GitHub execution and branch/environment protection settings were not changed or verified by this workstream. The parent adds browser/emulator jobs to the shared quality gate and owns its final combined run.
- Dart application lockfile enforcement does not freeze every native transitive dependency. The installed Stripe plugin still declares a `23.9.+` native SDK range, and Flutter's integration-test plugin declares `androidx.test:runner:1.2+`. Those upstream native ranges were not changed here. Retaining and qualifying the exact compiled artifact remains necessary; no complete Maven reproducibility claim is made.
- Signed iOS/Android release qualification remains separate. Native preflight fixture checks establish consistency validation, not ownership/configuration of Apple/Play/Firebase apps, protected signing material, App Check/provider setup, actual installed signing certificates or deployed association files. Enrollment status, isolated native staging configuration, iPad coverage and TestFlight/Play-installed device evidence must be verified with the owner and current services.
- Keep paid activation, refunds, biometrics and Wallet issuer delivery disabled as previously scoped. Do not treat a green local CI graph or this Admin debug executable as production acceptance, migration/recovery proof, owned pilot completion or the event-close plus 24-hour replay observation.
