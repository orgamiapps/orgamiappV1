## Isolation and evidence

`functions/tools/run-integration-tests.js --project demo-attendus-admin --suite flutter-browser` runs the Flutter driver only against `firebase.test.json`. `tools/run_flutter_integration.py` probes ten required callable handlers before launching a browser. A listening emulator socket, metadata 404, plain HTTP 200, or internal startup error does not satisfy readiness. Each run gets an unguessable fixture token, unique run ID, and a new evidence directory under `build/debugging-flutter-integration/`.

The WebDriver proxy installs request interception before forwarding successful session creation to Flutter. Local tests allow only loopback application services and read-only Firebase SDK, CanvasKit and font assets. Production Firebase, Attendus domains, Maps, email, and other provider calls are denied. Staging browser request policy permits only the exact staging origin/project/bucket, the fixture Auth API key, and the configured App Check/reCAPTCHA endpoints. Fixture accounts and event IDs must be present in the machine-owned manifest; accounts use the run-specific `example.test` namespace.

The emulator fixture server tracks created accounts/events, restores its prior configuration values, deletes linked owned documents and generated owned export objects, and verifies owned accounts/profiles/events were removed. Emulator trigger-generated metadata is ephemeral; this cleanup is not a proof of staging recovery or a broad destructive reset. Staging creation/cleanup belongs to the protected provisioner and its allowlisted ownership contract. The staging browser emits a separate run/project-bound manifest of anonymous UIDs actually created by successful anonymous Auth signup responses in its isolated contexts, including the cache-upgrade context; no Auth tokens or passwords are retained. The protected cleanup must reconcile that manifest as well as the seeded IDs.

The runner now constructs the Firebase CLI child environment from an explicit runtime allowlist. It removes inherited unrelated credentials and replaces raw environment dumps/bearer tokens in retained CLI diagnostics. Raw `firebase-debug.log` is not a publishable evidence artifact. Browser evidence avoids auth-form traces and passwords, stores signed URL expiry/job metadata without the signed URL, and includes manifest-bound assertion reports and screenshots of controlled fixture surfaces.

Staging protected API probes use the UID and token from the actual fixture user's browser login, kept only in memory. The controlled pilot uses the same browser-authenticated adapter and observed App Check token for every mutation; its separate protected ADC observer is restricted to reading scoped fixture setup, captures and receipts. Request interception is not an operating-system egress sandbox and does not prove complete interception of service-worker-owned requests. Cache qualification enables real workers and requires both replayed artifacts to be verified staging bundles.
